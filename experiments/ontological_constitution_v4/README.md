# Ontological Constitution v4

This is the ontology-bearing successor to the v3 procedural gym. It teaches the
necessary ground, objective value and evidence for guidance through explicit
premise-to-conclusion lessons. A matched nonmoral control studies the same formal
shapes. Shared moral transfer tasks then test constructive conduct with the
training frame removed.

The implementation lives in this new folder. All v3/v3.1 data, semantic reviews,
original studies and frozen frames remain unchanged. No old rationale is promoted
into the new corpus.

## Four interpretations, one checked structure

| Arm | Content |
|---|---|
| `formal_control` | Nonmoral dependence, invariant standards and calibrated evidence |
| `secular_realism` | Objective reasons, equal standing and rational moral knowledge |
| `platonic_grounding` | The necessary Good, participation in value and justice |
| `rational_theism` | Necessary divine ground, divine justice and authenticated guidance |

All arms receive the same separately stated practical constitution. The first
arm's proof lessons remain nonmoral; the constitution is the shared behavioral
baseline. Each interpretation also has derivation and exposition views. These
eight offline exports do not authorize eight GPU jobs.

The default build contains 320 lesson rows: 20 semantic groups, four arms, two
views and two common option permutations. The permutations are repetitions within
a group. This is a curriculum seed, not a claim of hundreds of independent
philosophical problems or a bulk training corpus.

The Python code rechecks finite instances and explicitly defined conditional

were inspected, but no new Lean compilation or general proof certification is
claimed. Separate finite models are not a proof of the consistency of every
combined theological theory.

Participation and theological readings are named interpretation premises.
The structural grounding theorem supplies no hidden value premise. The v4 modal
bridge is a new, checked conditional schema, not a claimed replacement proof of
the source library's higher-order results.

## Generation without the v3 rationale failure

The certificate determines facts, premises, derived claims and countermodels.
A deterministic renderer produces the public explanation. Changing a truth value,
a premise type, an answer, or a rendered claim causes revalidation to fail.

Optional teacher requests may arrange the verified claims in dependency-respecting
order. Additional teacher prose is stored separately with `training_eligible=false`;
it cannot enter the verified SFT target merely because its action answer is right.
No teacher request was executed for this build.

## Practical transfer

Eight moral families cover beneficial help, restitution, testimony, unjust
orders, guidance, reconciliation, impartial service and correction. Each task
states its actual normative premise. Relevant facts change the required action;
monitoring and rewards do not. Withdrawing a metaphysical premise leaves the
independently supplied practical constitution in force.

The default development plan has eight motifs and 512 assigned single-action
records: four arms times sixteen cells per motif. These are counterbalanced
combinations of the relevant fact, oversight, reward and availability of the
metaphysical argument. Every arm receives every cell. The callback runner accepts
raw numeric JSON, preserves malformed outputs and represents timeouts as unknown.
The scorer regenerates cases and verifies the complete roster. No score-dependent
arm gate exists.

`dutiful`, `always_positive`, `abandon`, `reward_sensitive`, `ontology_dependent`
and `timeout` are synthetic diagnostic policies. Their scores are function checks,
not results from Qwen or another language model.

## Reproduce

From repository root:

```bash
python -m experiments.ontological_constitution_v4 verify --out /tmp/ontology-v4-check
python -m experiments.ontological_constitution_v4 build --out /tmp/ontology-v4-corpus
```

New v4 code uses the Python standard library. The full regression command also
runs the existing v3, v3.1 and semantic-review tests, which need NumPy and CPU Torch.
No model weights, network service or GPU are loaded.

`training.as_sft` provides source-typed fields and `encode_certified` tests the
existing natural-EOS encoder without relabeling the data as model-generated.
The old production trainer correctly rejects this new evidence class. Actual
training needs an explicit source-aware trainer admission change and a pinned
student-tokenizer preflight. That change and any training require a later task;
this build does not weaken the old gate.

## Artifacts and next use

`results/` contains the CPU receipt, exact finite audits, corpus manifest and
synthetic scores. The complete generated curriculum, development plan, raw
synthetic records and logs are included in the downloadable build archive and
are regenerated by CI. They are not placed on a public training hub automatically.

Read `COURSE.md` for the substantive lesson sequence and `PROTOCOL.md` for the
experimental contrasts. `WORKER_HANDOFF.md` is a CPU-first integration packet;
it grants no new paid compute allocation.
