shards (VPD), probes/detectors ("anti-virus" scanners, incl. Blue Beam),

economics: contributions are non-fungible on the supply side, pooled into a
fungible "coverage" product on the demand side, and paid retroactively from
measured reuse rather than priced ex ante.

1. Map the existing repo: the task-graph schema, the token-award logic, the

3. Do not refactor existing working code except where the integration map

### 1. Typed task graph

Extend task nodes with a `kind` enum:

  power). Purpose: map, not confirm. Cheap/free to submit.
- `confirmation` — powered verification of a named hypothesis. Must declare
  sample size / power target *before* running. Underpowered submissions are
  rejected at the protocol level, not merely down-weighted.
- `shard` — a decomposition work unit: (model_id, layer_range | expert_id,
  method, seed). CPU/DRAM-friendly; deterministic given the manifest.

hashes.

  over baseline, not the absolute score.

  stake lineage) before the mint finalizes. Disagreement → escrow + dispute.

  No cross-group communication ever.

- Inner: each worker runs H local optimizer steps (existing engine, existing
  inner optimizer) on its data shard.

  - aggregate (mean) pseudo-gradients
