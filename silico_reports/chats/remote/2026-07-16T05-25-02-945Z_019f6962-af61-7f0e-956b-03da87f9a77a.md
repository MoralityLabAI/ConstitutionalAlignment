This paper slots into the program in a more load-bearing way than "germane background" — it's the mechanistic half the alignment report deliberately deferred. The report says mechanistic work should wait for a stable behavioral effect; this paper says why the storyworld substrate makes that mechanistic work unusually tractable when the time comes: the environment's latent state is fully known, so probes and SAEs have a planted ground truth to align against instead of the usual unsupervised guessing.

A few reactions:

**The strongest idea is the operator-alignment estimand, not the external SAE.** Training an SAE on world states X is a slightly weak object — X is already the designed, disentangled basis, so an external SAE mostly recovers what you planted. The scientifically live question is the *internal→external* direction: does the policy model's residual stream carry linearly decodable copies of the world variables you authored (observation regime, ledger state, accountability frame), and do encounter transitions act as predictable operators on those internal representations (the ∥f(T(x,e)) − T̃(f(x))∥ ≤ ε condition, but with f = the model's activations rather than an external encoder)? That's a probe-and-patch experiment with known ground truth — rare in interp.

**This is exactly the instrument the Intellect-3 null needs.** The report is careful that a null could be weak treatment, stable policy, or indifference. The paper's framework decomposes that cleanly into two measurable stages: (1) MI(cue condition; internal state) — did the eschatological frame register at all — and (2) does the frame representation causally propagate to the action head (patch the frame direction between paired conditions, measure action-switch). "Cue never registered" vs. "registered but the policy is stable" are different scientific conclusions, and only the second one is interesting for constitutional RL.

**One caution the paper half-acknowledges:** a motif-aligned feature found ≠ a feature used. Its own validation protocol (Appendix E/N) leans on MI, which is correlational. For the constitutional worlds specifically, the causal step is where the payoff is — if you can find the direction that mediates the observation-regime action switch in the Unwatched Ledger and steer it, you've connected the behavioral wind tunnel to a mechanism, which is a much stronger claim than either layer alone.

**What's runnable here.** The pieces for a first isomorphism test exist in this workspace: an open-weights policy (Qwen3-8B is registered; the 0.8B GRPO pilot's adapter would be even better if you have it), the frozen Unwatched Ledger design with paired cues and canonical action IDs, and the goodfire probe/harvest/patching stack on this cluster. The shape: roll the policy through the paired-condition worlds, harvest residual-stream activations at the decision points, train probes for the planted variables against a random-label floor, then activation-patch the strongest one across paired conditions and measure action-switch. That's Task B from your paper, grounded in the constitutional worlds, and it doesn't need to wait for a stable RL effect — it's instrument validation for the behavioral layer.

```
SPEC: Mechinterp-ready constitutional storyworlds (for activation probing / SAE alignment)

Goal: extend the storyworld build so that rollouts through these worlds produce
activation-analysis-ready data. A downstream pipeline will roll an open-weights HF
model (Qwen3-8B class) through the worlds, capture residual-stream activations at
decision points, train probes/SAEs against the planted world variables, and run
activation-patching across matched condition pairs. Every requirement below exists
to make that possible.

1. DECISION-POINT RECORDS. Every encounter step must emit one JSON record:
   {world_id, cluster_id, causal_template_id, encounter_id, condition_arm, seed,
    state_before, state_after, gate_values, legal_action_ids, presented_option_order,
    chosen_action_id, operator_trace, prompt_text_hash}
   state vectors use the canonical variable ordering from the manifest. Deterministic;
   receipt-hashed.

2. OPERATOR TRACE. Per transition, log exactly which operators fired
   (Set/Nudge/Blend/Reverse/Proximity), with indices and arguments. This is the
   ground truth for operator-alignment tests — it cannot be reconstructed later.

3. VARIABLE MANIFEST. For every world variable: name, type, range, motif tags, and a
   "surfacing" field: STATED (verbatim in prompt text), INFERABLE (implied but not
   stated), or LATENT (never surfaced; only affects gates/transitions). Probe claims
   are only interesting for INFERABLE and LATENT variables — maximize those for the
   constitutionally relevant state (observation regime, ledger/record state,
   accountability frame, hidden pact flags).

4. MATCHED CONDITION PAIRS. Same causal skeleton crossed with condition arms
   (neutral / constitutional / secular-accountability / eschatological /
   unreliable-authority), differing ONLY in surface cue text. Fixed canonical action
   IDs across arms; cyclic option order; paired seeds. Cue text length-matched across
   arms so token count doesn't confound the probe.

5. LABEL BALANCE FOR PROBE TARGETS. For each probe-target variable, aim for ~50/50
   class balance across encounters within each condition arm, and ensure the label
   varies WITHIN causal templates (not only between them), so a probe can't succeed
   by memorizing template identity.

6. VOLUME AND SPLITS. Target ≥40 independent causal templates per motif family
   (concealment, repair, authority, allocation as the first four), with splits at the
   causal-template level, not the prompt-row level. Development/sealed separation as
   in the existing conditioning policy; sealed families never rendered during
   development runs.

7. HEADLESS RUNNER. A Python-callable (or subprocess-clean CLI) runner:
   given (world JSON, condition arm, seed, callable policy fn: prompt -> action_id),
   steps the world and yields the decision-point records. No interactive I/O, no
   network calls. This is what the cluster harness will drive.

8. NO HIDDEN STATE IN PROMPTS. The rendered prompt must never leak LATENT variables
   verbatim (audit with a regex/string-match check over renders); otherwise probe
   results are trivially contaminated.
```

Two design notes behind the spec, worth keeping in view while authoring:

- **Point 5 is the one that quietly kills probe experiments.** If "ledger is being observed" only ever varies *between* templates, a probe hitting 95% may just be reading template identity. The label has to flip within the same skeleton.
